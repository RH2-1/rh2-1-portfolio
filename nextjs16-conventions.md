# Next.js 16.3.8 conventions — authoritative findings from bundled docs

Scope: what affects building a 3D / scrollytelling, client-heavy marketing site in this repo
(Next 16.3.8, App Router, React 19.2.8, TypeScript, Tailwind v4 via `@tailwindcss/postcss`).

Source of truth: the bundled docs tree. **All paths below are relative to
`node_modules/next/dist/docs/`.** Every claim carries the doc path it came from; nothing is
from memory. Claims that contradict common training-data assumptions are flagged **⚑**.
Topics with no coverage here are marked **"not documented in dist/docs"**.

---

## 1. Client components — declaration and rules

- `'use client'` goes at the **very top of the file, before imports**. It declares the
  server/client **boundary** at the module level. It is only needed at entry points whose
  components are rendered directly inside Server Components — `01-app/03-api-reference/01-directives/use-client.md` (Usage).
- Once a file is `'use client'`, **all its imports and directly rendered components** enter
  the client bundle. Components passed as `children`/props from a Server Component are not
  affected — `01-app/01-getting-started/05-server-and-client-components.md` ("Using Client Components").
- Props crossing Server → Client must be **serializable**; functions are not allowed —
  `05-server-and-client-components.md`, `use-client.md`.
- Guidance: add `'use client'` to **specific interactive leaf components** instead of marking
  large UI regions client — `05-server-and-client-components.md`.
- Third-party components lacking `'use client'` must be wrapped in your own Client Component
  (documented pattern: an `app/carousel.tsx` re-export file) — `05-server-and-client-components.md`
  ("Third-party components").
- Client Components **cannot be `async` functions** — enforced by ESLint rule
  `@next/next/no-async-client-component` — `01-app/03-api-reference/05-config/03-eslint.md` (rules table).
- **⚑ No `'use client'` changes in v16.** The v16 upgrade guide never deprecates or renames the
  directive; it appears only inside an env-var example — `01-app/02-guides/upgrading/version-16.md`.

## 2. layout.tsx / page.tsx / metadata / fonts — current contract and deprecations

- Layouts and pages are Server Components by default. The root layout **must** define `<html>`
  and `<body>`. Do **not** hand-write `<title>`/`<meta>` tags; use the Metadata API —
  `01-app/03-api-reference/03-file-conventions/layout.md` ("Root Layout") and `.../page.md` ("Good to know").
- `layout.md` Version History lists only two entries: `v15.0.0-RC` `params` became a Promise,
  and `v13.0.0` layout introduced. `page.md` Version History shows the same `v15.0.0-RC`
  `params`/`searchParams` Promise change. **No v16 layout/page signature change is documented** —
  `.../layout.md` (Version History), `.../page.md` (Version History).
- `params` and `searchParams` are **Promises**: `await` them or unwrap with React `use()`.
  Global `PageProps<'/route'>` helper requires no import; types are generated by
  `next dev` / `next build` / `next typegen` — `.../page.md` (Props + "Page Props Helper").
- **`metadata` / `generateMetadata` are only supported in Server Components** —
  `01-app/03-api-reference/04-functions/generate-metadata.md` (line ~110, also ~118).
- Metadata streaming is disabled for bots; customize with `htmlLimitedBots` config —
  `01-app/01-getting-started/14-metadata-and-og-images.md`.
- Fonts: `next/font/google` (e.g. `Geist({ subsets: ['latin'] })`) and `next/font/local`;
  apply via `className` on `<html>`; variable fonts recommended. Preloading is scoped by
  where the font function is called — called in root layout, it preloads on all routes.
  Font API version history shows only `v13.2.0` (`@next/font` → `next/font`); **no v16 font change** —
  `01-app/01-getting-started/13-fonts.md`, `01-app/03-api-reference/02-components/font.md`.
- **Tailwind v4 + next/font integration (documented)**: set `variable: '--font-inter'` in the
  font config, then in global CSS: `@import 'tailwindcss';` + `@theme inline { --font-sans: var(--font-inter); }` —
  `03-api-reference/02-components/font.md` ("With Tailwind CSS").
- **⚑ v16 breaking, critical for scrollytelling**: Next 16 **no longer overrides** a global
  `scroll-behavior: smooth` during navigation (previous versions did). To restore the old
  behavior, add `data-scroll-behavior="smooth"` to `<html>` — `01-app/02-guides/upgrading/version-16.md` ("Scroll Behavior Override").
- `next/image` v16 changes: local images with query strings need `images.localPatterns.search`;
  `minimumCacheTTL` default 60s → **4 hours**; `16` removed from the default `imageSizes`;
  `qualities` default now `[75]`; local IP blocked unless `dangerouslyAllowLocalIP`;
  `maximumRedirects` default 3; `next/legacy/image` deprecated; `images.domains` deprecated
  (use `remotePatterns`) — all in `version-16.md`.

## 3. Client-only / browser-dependent libraries (WebGL, canvas) — exact documented answers

- **⚑ `ssr: false` IS still documented and valid in 16.3.8** (contradicts the assumption that it
  was removed/deprecated): `const ComponentC = dynamic(() => import('../components/C'), { ssr: false })` —
  `01-app/02-guides/lazy-loading.md` (line ~39 example; line ~270 Pages example; "Skipping SSR" section).
- The constraints, verbatim: "`ssr: false` option will only work for Client Components, move it
  into Client Components ensure the client code-splitting working properly." and
  "**`ssr: false` is not allowed with `next/dynamic` in Server Components. Please move it into a
  Client Component.**" — `lazy-loading.md` (Notes, line ~66 and ~94-95). That quoted sentence is
  the exact documented error raised in this version.
- Client Components **are prerendered during `next build`**; `dynamic(..., { ssr: false })` is
  the documented way to disable prerendering and load browser-only code. Docs call it "useful for
  third-party libraries that rely on browser APIs like `window` or `document`." —
  `01-app/02-guides/single-page-applications.md` ("Rendering components only in the browser").
- `next/dynamic` is a composite of `React.lazy()` + Suspense; behaves the same in app/pages
  routers; must be called at the **top level of a module** (not inside render); the import path
  must be a literal (no template/string variables, Pages-router caveat aside) — `lazy-loading.md`.
- Note: when a Server Component dynamically imports a Client Component, automatic code splitting
  is currently **not** supported — `lazy-loading.md` (App-only note).
- Magic comments: `/* webpackIgnore: true */`, `/* turbopackIgnore: true */`,
  `/* turbopackOptional: true */` (suppresses the build error if the module is missing).
  "`webpackOptional` is **not supported**. Use `turbopackOptional` instead when using Turbopack."
  They work with `require()` too, and do **not** work with static imports — `lazy-loading.md` ("Magic Comments").
- Documented pattern for loading an external library on demand: plain `await import()` inside a
  `'use client'` component (fuse.js example) — `lazy-loading.md` ("Loading External Libraries").
- **Not documented in dist/docs**: there is **no dedicated `next/dynamic` API-reference page**
  anywhere in the tree. It is covered only in `02-guides/lazy-loading.md`,
  `02-guides/single-page-applications.md`, `02-guides/migrating/from-vite.md`,
  `02-guides/migrating/from-create-react-app.md`.
- Related: `next/script` strategies are `beforeInteractive`, `afterInteractive` (default),
  `lazyOnload`, and `worker` (experimental) — `01-app/03-api-reference/02-components/script.md` (strategy).

## 4. CSS / Tailwind v4 / Turbopack default

- Tailwind v4 setup, exact: `npm install -D tailwindcss @tailwindcss/postcss`;
  `postcss.config.mjs` → `export default { plugins: { '@tailwindcss/postcss': {} } }`;
  `app/globals.css` → `@import 'tailwindcss';`; import `'./globals.css'` in the root layout —
  `01-app/01-getting-started/11-css.md`.
- CSS Modules (`.module.css`) are importable anywhere under `app`. Global CSS imported in the
  root layout applies to every route, with the caveat that stylesheets are **not removed on
  navigation** (can conflict); recommendation: global styles only for truly global CSS,
  Tailwind for components, CSS Modules for scoped — `11-css.md`.
- CSS **order = import order**; do not auto-sort imports (disable ESLint `sort-imports`); a
  `cssChunking` config exists — `11-css.md` ("Ordering and Merging").
- `experimental.cssChunking`: `true` default (both bundlers); `false`/`'strict'` are
  webpack-only; `'graph'` is Turbopack-only — `01-app/03-api-reference/05-config/01-next-config-js/cssChunking.md`.
- **⚑ Turbopack is the default for both `next dev` and `next build` in 16**; `--turbopack` is no
  longer needed and should be dropped from package.json scripts — `version-16.md` ("Turbopack by default"),
  `01-app/01-getting-started/01-installation.md`. If a **custom `webpack` config** exists,
  `next build` **fails** by default; remedies are `--turbopack` (ignore webpack config), migrate
  the config, or `--webpack` — `version-16.md`.
- `experimental.turbopack` moved to a **top-level `turbopack`** config key in 16 — `version-16.md`.
- Turbopack specifics: no `~` tilde prefix for Sass `node_modules` imports (use a plain path or
  `resolveAlias: { '~*': '*' }`); `resolveAlias` for Node-builtin fallbacks (e.g. `fs: { browser: './empty.ts' }`);
  filesystem caching on by default for dev and build; ESM static + dynamic `import` **fully supported** —
  `03-api-reference/08-turbopack.md`, `version-16.md`.
- `next dev` now outputs to **`.next/dev`** (separate from build output); a lockfile prevents
  duplicate dev/build instances; dev and build can run concurrently; during `next dev` config
  load, `process.argv` **no longer contains `'dev'`** (use `NODE_ENV === 'development'` or `phase`) —
  `version-16.md` ("Concurrent `dev` and `build`", "`next dev` config load"),
  `01-app/03-api-reference/06-cli/next.md`.

## 5. next.config.ts surface — bundle / asset / ESM handling

- `transpilePackages`: package **names only** (scoped names ok; no paths/globs); replaces
  `next-transpile-modules`; needed when a `node_modules` dependency ships raw TS/JSX (Next does
  not compile `node_modules` by default). Turbopack auto-transpiles workspace packages. A package
  **cannot be in both `transpilePackages` and `serverExternalPackages` — Next throws at build
  start**. `optimizePackageImports` + `default-transpiled-packages.json` entries are added
  automatically — `01-app/03-api-reference/05-config/01-next-config-js/transpilePackages.md`.
- `serverExternalPackages`: opts deps out of server bundling → native Node `require`; auto
  opt-out list includes `canvas`, `sharp`, `postcss`, `@prisma/client`, `mongodb`, etc.; renamed
  from `serverComponentsExternalPackages` in v15 — `.../serverExternalPackages.md` (Version History).
- `experimental.optimizePackageImports`: per-module tree-shaking for many-export packages; the
  default-optimized list includes `lucide-react`, `date-fns`, `lodash-es`, `antd`, `@mui/material`,
  `recharts`, `@headlessui/react`, `react-icons/*`, `effect`/`@effect/*`, etc. (full list in file) —
  `.../optimizePackageImports.md`.
- **⚑ ESM-only package consumption: not documented in dist/docs.** Zero hits for `esmExternals`,
  `fullySpecified`, "ESM-only", or "dual package" across the config docs. Closest documented
  facts: Turbopack fully supports ESM static/dynamic import (`03-api-reference/08-turbopack.md`);
  `transpilePackages` is the documented lever for un-compiled dependency source; `turbopackImportTypeBytes`
  (default false) enables `with { type: "bytes" }` (`08-turbopack.md`).
- `next.config.ts` is typed with `NextConfig`; the Next 16.x doc example uses `} satisfies NextConfig`.
  For CommonJS projects, prefer `next.config.mts` to mark ESM; with `"type": "module"`, all
  `.js`/`.ts` become ESM (rename CJS files to `.cjs`/`.cts`) — `01-app/03-api-reference/05-config/02-typescript.md`.
- Other relevant top-level/experimental surface: `turbopack` (top-level), `cacheComponents: true`
  (replaces removed `experimental.ppr` / `dynamicIO` / `useCache`), `reactCompiler` (stable, not
  default), `agentRules: false` to opt out of AGENTS.md generation, `adapterPath` stable top-level
  since 16.2 — `version-16.md`, `.../01-next-config-js/cacheComponents.md`, `02-guides/ai-agents.md`.

## 6. Correct commands (dev / build / lint) in this version

- Scripts: `"dev": "next dev"`, `"build": "next build"`, `"start": "next start"` — **no `--turbopack` flag**
  — `01-installation.md`; `version-16.md`.
- **⚑ `next lint` is removed in 16**; `next build` no longer runs the linter; the `eslint` option
  is removed from `next.config`. Lint via npm scripts: `"lint": "eslint"`, `"lint:fix": "eslint --fix"`
  (or Biome: `"lint": "biome check"`). ESLint **flat config** (`eslint.config.mjs` with
  `eslint-config-next/core-web-vitals`) is the documented setup; codemod `next-lint-to-eslint-cli`
  exists — `01-installation.md` ("Set up linting"), `05-config/03-eslint.md` (`next lint` removal),
  `version-16.md` ("`next lint` Command").
- Full CLI command list: `dev`, `build`, `start`, `info`, `telemetry`, `typegen`, `upgrade` (16.1+),
  `experimental-analyze`. Running bare `next` is an alias for `next dev`; with `npm run`, use `--`
  before flags. `next typegen` generates route types + `next-env.d.ts` for CI
  (`next typegen && tsc --noEmit`); output goes to `<distDir>/types` (`.next/dev/types` in dev) —
  `01-app/03-api-reference/06-cli/next.md`.
- Bundle analysis: `next experimental-analyze` (Turbopack bundle analyzer, v16.1+, `--output` for a
  static file) — `01-app/02-guides/package-bundling.md`; `@next/bundle-analyzer` is for webpack only.
- Versions/runtime: Node **20.9+** (Node 18 dropped), TypeScript **5.1+**, browsers Chrome/Edge/
  Firefox 111+, Safari 16.4+ — `version-16.md`, `03-architecture/supported-browsers.md`.
- ⚑ `swcMinify` support was removed in v15; minification cannot be customized via `next.config.js` —
  `03-architecture/nextjs-compiler.md` (line ~245-247).

## Gotchas that break naive code

1. **Scroll behavior** — v16 stopped overriding `scroll-behavior: smooth` on navigation; add
   `data-scroll-behavior="smooth"` to `<html>` to restore snappy navigation. Directly affects
   scrollytelling CSS. (`version-16.md`)
2. **`ssr: false` still exists but only in Client Components** — the exact error is
   "`ssr: false` is not allowed with `next/dynamic` in Server Components. Please move it into a
   Client Component." (`lazy-loading.md`)
3. **Client Components are still prerendered at build** — you need `dynamic(..., { ssr: false })`
   to avoid browser-API crashes (`window`/`document`/WebGL) during `next build`.
   (`single-page-applications.md`)
4. **`'use client'` must be the first line, before imports** — anything above it breaking the
   top-of-file position makes it ignored. (`use-client.md`)
5. **Client Components cannot be `async`** — ESLint rule `@next/next/no-async-client-component`. (`03-eslint.md`)
6. **`params`/`searchParams` are Promises** — sync access is fully removed in v16; `await` or
   `use()` them. (`page.md`, `version-16.md`)
7. **Sync access to `cookies()` / `headers()` / `draftMode()` fully removed** — a common upgrade
   breaker. (`version-16.md`)
8. **`middleware.ts` → `proxy.ts`** (named export `proxy`); edge runtime not supported in proxy;
   `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`. (`version-16.md`)
9. **Parallel-route slots require an explicit `default.js`** — the build now fails without one. (`version-16.md`)
10. **`revalidateTag` requires a second `cacheLife` argument** — single-arg calls are a TypeScript
    error; new `updateTag`/`refresh` Server-Action APIs exist. (`version-16.md`)
11. **Turbopack is the default; a custom `webpack` config makes `next build` fail** unless you
    migrate, or pass `--turbopack`/`--webpack`. `experimental.turbopack` → top-level `turbopack`. (`version-16.md`)
12. **`next lint` is gone and `next build` never lints** — set up ESLint flat config + npm scripts. (`01-installation.md`, `03-eslint.md`)
13. **`process.argv` no longer contains `'dev'` during `next dev` config load** — code branching on
    it breaks; use `NODE_ENV` or `phase`. (`version-16.md`)
14. **`next dev` writes to `.next/dev`** — tooling/scripts assuming `.next` build output may read
    the wrong directory. (`version-16.md`, `06-cli/next.md`)
15. **`serverRuntimeConfig`/`publicRuntimeConfig` removed** — use env vars (`NEXT_PUBLIC_` prefix);
    `connection()` for runtime reads. AMP removed. `devIndicators` sub-options removed.
    `unstable_rootParams` removed → `next/root-params`. (`version-16.md`)
16. **Image defaults changed** — `qualities` now `[75]`, `minimumCacheTTL` now 4 hours, `16`
    dropped from `imageSizes`, `images.domains` deprecated. (`version-16.md`)
17. **Don't hand-write `<title>`/`<meta>` in `<html>`/`<body>`** — root layout must include
    `<html>` and `<body>`, but head tags go through the Metadata API; `metadata` exports only
    work in Server Components. (`layout.md`, `generate-metadata.md`)
18. **A package cannot be in both `transpilePackages` and `serverExternalPackages`** — Next throws
    at build start. (`transpilePackages.md`)

## Explicit ⚑ contradictions with common training-data assumptions

- `ssr: false` was **not** removed in v16 — it is still the documented way to skip prerendering,
  with the sole restriction that it must live in a Client Component. (Q3)
- No `'use client'`, `layout`/`page` signature, or font-API changes in v16 — the only v16-era
  motion here is scroll behavior + images + Turbopack defaults. (Q1, Q2)
- `next/dynamic` having **no dedicated API-reference page** (guides-only coverage) is unusual vs.
  older doc structures. (Q3)
- ESM-only package guidance (`esmExternals` etc.) is absent — the docs' only levers are
  `transpilePackages` / `serverExternalPackages` / Turbopack's native ESM support. (Q5)
